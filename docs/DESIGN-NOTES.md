# 설계 메모

[README](../README.md)의 "핵심 설계"를 자세히 적은 문서입니다. 세팅 방법은 [세팅 가이드](SETUP.md)에 있습니다.

## 왜 Apps Script인가

처음에는 GitHub Actions에서 Node 스크립트로 크롤하고(서비스 계정 키로 시트에 쓰기), 검증은 따로 예약한 AI 에이전트가 하는 구조로 만들었습니다. 이것을 시트 하나에 붙은 스크립트로 합치자 크롤용 서버·스케줄러·키 파일이 모두 필요 없어졌고, 시트를 쓰는 사람이 메뉴에서 직접 다시 돌려 볼 수도 있게 됐습니다. 서비스 계정은 홈페이지 빌드가 승인된 행을 읽을 때만 씁니다.

## AI는 추천만 합니다

잘못 게시되면 회사 홈페이지에 다른 회사 기사가 걸립니다. 그래서 AI는 `ai_verdict`·`ai_reason`에만 쓰고 `status`는 코드가 절대 쓰지 않습니다. "등장은 하지만 주제가 아닌 기사"는 `reject`가 아니라 `review`로 두게 해서, 게시 여부를 사람이 고르게 했습니다.

## 1차는 넓게, 2차는 좁게

인터뷰·기획 기사는 제목에 회사 이름이 없는 경우가 많아, 제목에 없으면 네이버가 주는 본문 조각까지 봅니다. 그만큼 이름만 같은 회사가 많이 걸리므로 `DENY`와 설립일 하한으로 한 번 거르고, AI가 기사를 직접 찾아 읽고 다시 거릅니다.

## 중복은 제목 또는 주소로

같은 기사가 언론사 이름이나 추적 파라미터만 달리해서 다시 들어옵니다(`utm_source`가 붙은 주소로 같은 기사가 두 번 들어온 적이 있습니다). 그래서 정규화한 제목이나 추적 파라미터를 지운 주소 중 하나만 같아도 중복으로 봅니다. 언론사명은 AI가 나중에 고치기 때문에 중복 판단 기준에서 뺐습니다(넣으면 고친 다음 날 같은 기사가 새 기사처럼 보입니다).

## 구글 뉴스 링크는 원문이 아닙니다

구글 뉴스 RSS의 링크는 `news.google.com` 리다이렉트라서, AI가 "제목 + 언론사"로 웹 검색해 원문 주소를 찾아 덮어씁니다. 네이버는 원문 주소를 바로 줍니다.

## 날짜는 한국 기준으로

발행 시각을 UTC 날짜로 저장하면 오전 9시 전에 나온 기사가 하루 앞 날짜가 되고, 설립일 하한에 걸려 버려지는 경우가 생깁니다.

## 실패해도 행을 망가뜨리지 않습니다

| 상황 | 처리 |
| --- | --- |
| 시트 1행에 필수 열이 없음 (열 이름 오타 등) | 크롤·검증을 시작하기 전에 멈추고 빠진 열 이름을 알림(메뉴 실행은 창으로, 매일 자동 실행은 실행 오류로 남음). 그대로 돌면 결과를 쓸 열이 없어 같은 행을 매 실행마다 다시 검증(과금)한다 |
| API 호출 실패 | 그 행의 `ai_verdict`를 비워 둔다. 채우면 '검증 끝'으로 보고 영영 건너뛰기 때문 |
| 400·401 같은 요청 오류 | 남은 행도 똑같이 실패하므로 바로 멈추고 원인을 알림 (크레딧 부족, 모델 이름 오타 등) |
| 429·5xx | 그 행만 다음 실행으로 미루고 나머지는 계속 |
| 네트워크 오류·시간 초과 | 429·5xx와 같이 그 행만 다음 실행으로 미루고 나머지는 계속 (실행 전체가 죽어 Slack 요약이 빠지지 않게) |
| 응답이 `max_tokens`에서 잘림 | 설정 문제이므로 올려야 할 값을 그대로 알림 |
| 웹 검색 중 `pause_turn` | 받은 턴을 그대로 붙여 이어 보냄(첫 요청을 포함해 최대 4번, 이어 보내기는 최대 3번). 이어 달라는 말은 덧붙이지 않는다 |
| 모델이 판단을 거절(`refusal`) | `review`로 남겨 사람이 보게 함 (그냥 두면 매 실행마다 같은 행을 다시 부른다) |
| 응답에서 JSON을 못 읽음 | 그 행만 건너뛰고 다음 실행 때 재시도 |
| 다른 실행이 돌고 있음 | 크롤·AI 검증·매일 자동 실행은 잠금으로 한 번에 하나만 돈다. 잠금을 못 얻으면 메뉴는 창으로, 매일 실행은 Slack으로 알리고 건너뜀 |
| 검증하는 사이 행이 옮겨지거나 지워짐 | 결과를 쓰기 직전에 같은 기사(주소·제목)인지 확인하고, 옮겨졌으면 주소로 다시 찾아 씀. 못 찾으면 쓰지 않고 다음 실행에 맡김 |

## 실행 시간 6분 제한

Apps Script 한 번 실행은 약 6분까지라서 한 번에 6건까지만 검증하고, 실행이 4분 30초를 넘으면 새 행을 시작하지 않습니다. 남은 건은 다음 실행 때 이어서 합니다.
