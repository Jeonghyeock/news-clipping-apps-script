# news-clipping-apps-script

회사 이름이 나온 기사를 매일 찾아 구글 시트에 모으고, AI가 먼저 "정말 우리 회사 기사인지, 원문은 어디인지, 이미 올린 기사와 겹치는지"를 확인해 두는 도구입니다. 사람은 시트에서 게시할 기사만 고르고 메뉴 한 번으로 홈페이지에 반영합니다.

실제 회사 홈페이지의 '언론 보도' 섹션을 이 방식으로 운영하고 있고, 이 저장소는 회사 이름과 검색어를 예시값으로 바꾼 공개본입니다.

> Claude Code와 함께 만들었습니다.

- **서버 없음**: 크롤링, AI 검증, 알림, 매일 자동 실행이 전부 구글 시트에 붙은 Apps Script 안에서 돕니다.
- **시트가 곧 관리 화면**: 개발자가 아니어도 시트에서 승인할 수 있습니다.
- **최종 결정은 사람이**: AI는 추천(`ai_verdict`)과 이유(`ai_reason`)만 쓰고, 게시 여부(`status`)는 사람이 정합니다.

**문서**: [세팅 가이드](docs/SETUP.md) (시트 구조, 0~7단계 세팅, 비용, 모델 바꾸기) · [설계 메모](docs/DESIGN-NOTES.md) (왜 이렇게 만들었는지, 실패 처리)

## 흐름

1. 매일 오전 9시 트리거(또는 메뉴에서 직접 실행)가 시작합니다.
2. 구글 뉴스 RSS와 네이버 뉴스 API에서 회사 이름으로 검색합니다.
3. 코드가 1차로 거릅니다: 회사 이름 정규식, 동명이의·설립일 이전 기사 제외, 제목·주소 중복 제외.
4. 남은 후보를 시트에 `pending` 행으로 추가합니다.
5. Claude가 웹 검색으로 기사를 확인해 원문 주소·언론사명을 채우고 `approve` / `review` / `reject`를 추천합니다.
6. Slack으로 요약을 보냅니다.
7. 사람이 시트에서 `status`를 `approved` / `rejected`로 바꾸고 메뉴 **사이트 반영**을 누릅니다.
8. 홈페이지 빌드가 `approved` 행만 읽어 `news.json`을 만듭니다([`site/fetch-approved-news.mjs`](site/fetch-approved-news.mjs)).

## 핵심 설계

- **[AI는 추천만, 게시는 사람이](docs/DESIGN-NOTES.md#ai는-추천만-합니다)**: AI는 `ai_verdict`·`ai_reason`에만 쓰고, `status`는 코드가 쓰지 않습니다.
- **[1차는 넓게, 2차는 좁게](docs/DESIGN-NOTES.md#1차는-넓게-2차는-좁게)**: 코드는 본문 조각까지 넉넉히 받고, AI가 기사를 직접 읽어 다시 거릅니다.
- **[중복은 제목 또는 주소로](docs/DESIGN-NOTES.md#중복은-제목-또는-주소로)**: 정규화한 제목이나 추적 파라미터를 지운 주소 중 하나만 같아도 중복으로 봅니다.
- **[날짜는 한국 기준으로](docs/DESIGN-NOTES.md#날짜는-한국-기준으로)**: UTC로 저장하면 오전 9시 전 기사가 하루 앞 날짜가 되어 설립일 하한에 걸립니다.
- **[실패해도 행을 망가뜨리지 않습니다](docs/DESIGN-NOTES.md#실패해도-행을-망가뜨리지-않습니다)**: 실패한 행은 비워 두고 다음 실행에 다시 검증하며, 다른 기사의 행에는 결과를 쓰지 않습니다.
- **[Apps Script를 고른 이유](docs/DESIGN-NOTES.md#왜-apps-script인가)**: 크롤용 서버·스케줄러·키 파일 없이 시트 하나에서 전부 돕니다.

## 비용

기사 1건마다 웹 검색 최대 $0.03(최대 3회)과 토큰 비용(`claude-opus-4-8` 100만 토큰당 입력 $5 / 출력 $25)이 듭니다. 자세한 내용은 [세팅 가이드의 비용](docs/SETUP.md#비용)에 있습니다.

## 테스트

```bash
npm install
npm test
```

`Code.gs`는 Apps Script 전용이라 import할 수 없어서, Node의 `vm`에서 파일을 그대로 실행하고 Apps Script 전역 객체(`UrlFetchApp`, `PropertiesService`, `LockService`, `SpreadsheetApp`)와 시트를 가짜로 넣어 검증합니다([`test/load-script.mjs`](test/load-script.mjs)).

| 대상 | 내용 |
| --- | --- |
| 후보 정리 | 추적 파라미터 제거, 제목 정규화, 한국 날짜 변환, 본문 조각 판정과 동명이의 제외, 설립일 하한 |
| `crawlCore_` | 제목·주소 중복, 같은 실행 안의 중복, 설립 이전·무관한 기사 제외, 날짜순 정렬, 열 순서가 바뀐 시트, 필수 열이 없는 시트, 날짜 칸 일반 텍스트 |
| `verifyOne_` | `pause_turn` 이어 보내기, `max_tokens` 잘림, 429·5xx와 400 구분, 네트워크 오류, `refusal`, 느슨한 JSON 읽기 |
| `verifyCore_` | 실패한 행 비워 두기, '우리 회사 아님'·중복은 `reject`, `status` 칸 안 건드림, 400이면 즉시 중단, 한 번에 6건, 4분 30초 시간 제한, 필수 열 확인, 네트워크 오류 뒤 다음 행 계속, 검증 중 옮겨지거나 지워진 행 |
| 메뉴·매일 실행 | 다른 실행이 돌고 있으면 건너뜀, 끝나면(오류로 끝나도) 잠금 해제, 네트워크 오류에도 Slack 요약 |
| 홈페이지 읽기 | 열 이름으로 객체 만들기, `approved`만 최신순, 날짜 형식 맞추기, 자격 증명이 없을 때 빈 목록 |

실제 구글 서비스(메뉴, 트리거, 잠금, 시트 API와 서식)와 Anthropic API에 붙는 부분은 테스트하지 않습니다. 홈페이지 읽기 스크립트는 가짜 키로 구글 인증 서버까지 요청이 가는 것만 확인했습니다.

## 한계

- `image`와 `description`은 사람이 채웁니다. AI가 대표 이미지를 가져오거나 요약을 쓰지는 않습니다.
- 매일 자동 실행은 하루 6건까지 검증합니다. 후보가 많은 날은 메뉴에서 **AI 검증**을 더 누르거나 다음 날 이어서 검증됩니다.
- 구글 뉴스 RSS는 공식 API가 아니라서 형식이 바뀌면 크롤이 조용히 0건이 될 수 있습니다.
- 영문 홈페이지용 번역은 들어 있지 않습니다.

```
  fetch-approved-news.mjs  홈페이지 빌드 전에 approved 행만 읽어 news.json 생성

  SETUP.md                 시트 구조, 세팅 0~7단계, 비용, 모델 바꾸기

test/                      Node 테스트 (Code.gs를 vm에서 실행)
```
